# DISC-03 — Жизненные циклы двух игровых ролей

**Дата:** 2026-11-08  
**Статус:** утверждено владельцем проекта 2026-11-08; открытые вопросы отдельно распределены по следующим задачам.  
**Задача:** [#10](https://github.com/Bleakest/Virtual-competitive-ecosystem/issues/10)

> В названии исходной задачи осталось «трёх ролей», но DISC-01 уже исключил организатора (DEC-012). **Здесь описаны только игрок и менеджер**. Планирование/проведение турниров — обязанность игровой системы, а не третий тип персонажа.

## 1. Общий контур — принято

- Один аккаунт владеет несколькими самостоятельными персонажами; у каждого неизменная роль.
- Мир существует непрерывно и живёт по реальному времени. Смена персонажа/выход пользователя не приостанавливает событие.
- Любой матч рассчитывается единой серверной симуляцией; решения людей и NPC относятся к одному состоянию игры.
- В полном видении объединены **карьерное развитие**, **предматчевые решения** и **решения во время ключевых эпизодов**. Это ориентир, а не обязательства первого релиза.
- Игрок ограничен одной дисциплиной, менеджер может работать с несколькими.

## 2. Игрок — утверждённый жизненный цикл

```text
Выбор роли PLAYER и дисциплины
  → создание PlayerProfile
  → самостоятельная карьера (без команды или в команде)
  → тренировки / прогресс / подготовка / матчи / результаты
  → смена команды или продолжение карьеры
  → архивирование (опционально; история сохраняется)
```

| Этап | Действие пользователя | Реакция мира |
|---|---|---|
| Создание | Выбирает имя, PLAYER, одну дисциплину | Создаёт `Character` и `PlayerProfile`; фиксирует дисциплину навсегда |
| Начало карьеры | Получает доступные варианты участия в дисциплине | Персонаж становится участником соответствующей экосистемы; способы поиска команды — DISC-06 |
| Развитие | Выбирает тренировки / направления развития | Система рассчитывает изменение характеристик по правилам дисциплины (формулы — DISC-05/08) |
| Социально-командный этап | Принимает доступные приглашения, вступает / выходит из команды | Меняет членство с учётом будущих контрактных правил (DISC-06) |
| Подготовка | Просматривает календарь, задаёт установки до дедлайна | Установки сохраняются для предстоящего события |
| Матч | Подключается в назначенное **реальное время** и при доступном эпизоде выбирает действие | Сервер применяет решение к одной симуляции и транслирует обновления |
| После матча | Изучает итог, статистику, последствия | Мир фиксирует результат, прогресс и историю карьеры |
| Отсутствие | Не приходит к началу матча | Матч **не отменяется автоматически**; поведение его участника будет задано в DISC-07/08 |
| Завершение | По желанию архивирует карьеру | Запрещаем новые игровые действия, но сохраняем историю и результаты; условия — DISC-10 |

**Утверждённые состояния** `Character.status = ACTIVE | ARCHIVED`. Статусы «в команде / свободен», «заявлен / не заявлен», «онлайн / офлайн» — **отдельные измерения**, а не одно большое состояние персонажа. Нельзя делать «игрок в матче» новым типом персонажа.

### Ограничения игрока

- Не может сменить дисциплину или роль существующего персонажа.
- Не получает менеджерских полномочий только потому, что состоит в команде.
- Может влиять лишь на действия, разрешённые ролью, составом, статусом события и дедлайнами.
- Не гарантировано, что каждое событие содержит интерактивный эпизод или что пользователь обязательно находится онлайн.

## 3. Менеджер — утверждённый жизненный цикл

```text
Выбор роли MANAGER
  → создание ManagerProfile
  → поиск / получение управленческих полномочий
  → управление командой и подготовка
  → матч: тренерские решения
  → результаты / изменение состава и стратегии
  → продолжение или окончание назначения
  → новое назначение / архивирование
```

| Этап | Действие пользователя | Реакция мира |
|---|---|---|
| Создание | Выбирает имя и MANAGER | Создаёт `Character` и `ManagerProfile` **без закрепления за дисциплиной** |
| Вход в профессию | Ищет или получает доступ к команде | Система оформляет управленческое назначение (DISC-06) |
| Управление | Изучает состав, задаёт планы подготовки и расстановку | Платформа проверяет полномочия и сохраняет изменения |
| Развитие | Работает над командой, тактикой, возможностями клуба | Расчёт командного/менеджерского прогресса — отдельные правила DISC-06/08 |
| Соревнование | Подаёт заявку, выбирает доступных участников и установки | Система проверяет регламент турнира, состав и дедлайны (DISC-06/07) |
| Матч | В реальном времени принимает **тренерские/тактические**, а не игровые действия спортсмена | Одно состояние симуляции учитывает решения команды, игроков и NPC |
| После матча | Анализирует итог и меняет подготовку | Результат сохраняется в истории команды и менеджера |
| Смена работы | Завершает назначение и получает другое | Права на прежнюю команду прекращаются; достижения менеджера сохраняются |
| Отсутствие | Не приходит к матчу | Матч продолжается, а способ автопринятия решений определяется DISC-07/08 |
| Завершение | Архивирует карьеру | Прекращаются новые управленческие действия без потери исторических результатов |

**Утверждённые состояния:** сам `Character` — `ACTIVE | ARCHIVED`; «без команды / при команде» вычисляется из активных `ManagementAssignment`. Менеджер не превращается в игрока. Поддержка нескольких дисциплин не означает, что уже решено, **сколькими командами можно управлять одновременно**: это вопрос DISC-06/10.

### Ограничения менеджера

- Не имеет права принимать решения за персонажа-игрока, если это не доступное тренерское решение в рамках команды.
- Не меняет состав/план после закрытия соответствующего окна времени.
- Может действовать только по отношению к командам, на которые у него есть действующие полномочия.
- Не создаёт произвольные матчи или турниры «как организатор». Этим управляет платформа.

## 4. Механика реального времени — граница DISC-03

Пример последовательности для **обеих** ролей:

```text
Запланировано → Окно подготовки → Матч идёт → Матч завершён
  ↳ менеджер задаёт тактику     ↳ менеджер выбирает допустимые тренерские действия
  ↳ игрок задаёт установки      ↳ игрок выбирает доступные решения эпизодов
                                ↳ отсутствующих обслуживают правила автоматики/NPC
```

Это **схема продукта**, а не утверждение конечного автомата матчей. Точные стадии, длительности, таймзоны, дедлайны, разрешение конкурирующих решений и алгоритм симуляции относятся к **DISC-07/08**.

Инвариант: решение принимается только если персонаж **имеет право действовать в данном матче** и соответствующее временное окно **открыто** по серверному времени. Опоздавшие решения не переписывают прошлое.

## 5. Минимальные сценарии для проверки

1. Создать PLAYER → выбрать дисциплину → пройти развитие → подготовиться → подключиться к событию → увидеть результат; персонаж остаётся той же роли и дисциплины.
2. Создать MANAGER → получить командные полномочия → настроить тактику → принять доступное решение во время матча → увидеть результат; он не становится спортсменом.
3. Войти другим персонажем того же аккаунта: карьеры не объединяются, запланированные события продолжаются.
4. Не прийти на запланированный матч: событие проходит по системным правилам; конкретный алгоритм офлайн-замещения ещё подлежит определению.
5. Попытаться принять решение за чужой аккаунт, чужую команду или вне временного окна: сервер отклоняет действие.
6. Системная лига организует матч без персонажа-организатора.
