# DISC-10 — Границы первого MVP

**Дата:** 2026-11-08  
**Статус:** рабочий объём MVP выбран по делегированию владельца; параметры баланса и детали реализации можно корректировать после игрового теста без пересмотра концепции.  
**Issue:** [#8](https://github.com/Bleakest/Virtual-competitive-ecosystem/issues/8)

## 1. Определение первой версии

**Цель MVP:** доказать не просто создание аккаунтов, а **реальное участие человека в общем запланированном матче, который идёт во времени, реагирует на решения и завершается даже при нулевом онлайне**.

**Выбранная первая дисциплина:** **упрощённый футбол 11×11**. Это решение **только для первого релиза**, не отказ от других видов спорта и киберспорта. Причина: понятная всем событийная модель (атаки, удары, голы), не требуется оружейная экономика или подключение к чужой игре. Параллельно реализовывать Counter-Strike-подобную дисциплину на старте **не нужно**.

**Тип соревнований MVP:** выставочные матчи между системными клубами, без лиг/сезонов/турнирной таблицы. Назначает система. Матч **примерно 10 реальных минут** (настраиваемая длительность для тестов), с последовательным серверным расчётом и несколькими интерактивными окнами. Не заявлять, что это реалистичная длительность 90 минут футбола.

## 2. Что обязательно работает

| Область | MVP — реально работающие возможности |
|---|---|
| Аккаунт | Регистрация, вход, выход, защищённая сессия; пароль хранится только как надёжный хеш |
| Персонажи | Создать PLAYER/ MANAGER, выбрать, переключиться, неизменяемые роли; PLAYER привязан к футбольной дисциплине |
| Мир | Один общий мир с системным календарём, постоянными командами и NPC; события продолжаются при отсутствии клиентов |
| Команды | Несколько системных клубов; игрок занимает доступный слот до блокировки заявки, менеджер получает свободное назначение; права проверяются сервером |
| Участники | Футбольные составы **11×11**, включая NPC для незанятых мест; один человек и NPC могут играть за одну команду |
| Календарь | Видно ближайший матч, время начала в локальном часовом поясе, состояние и дедлайны |
| Подготовка | Менеджер задаёт `ATTACK/BALANCED/DEFEND`; игрок видит доступные предматчевые установки (на первом шаге допускается только один простой выбор) |
| Матч | Начинается в серверное время, LIVE-счёт/события/прогресс обновляются в процессе, **не предрассчитанный фильм** |
| Влияние | Игрок и менеджер имеют хотя бы по **одному типу реально применяемого интерактивного решения**; выбор принимается до дедлайна и меняет расчёт вероятностей/состояния |
| Офлайн | NPC и автодействия за отсутствующих выполняются по правилам; матч доходит до FINISHED без онлайн-пользователей |
| Результаты | Счёт, победитель или ничья, краткая статистика, история матчей; финализация один раз |
| Наблюдаемость | Логи запуска/ошибок/финализации, восстановление сохранённого состояния после рестарта процесса |

Для полной демонстрации достаточно, чтобы **два разных аккаунта** могли участвовать в одном событии, один как PLAYER, второй как MANAGER; оставшиеся позиции закрываются NPC. Не нужен большой онлайн.

## 3. Что намеренно НЕ делаем в первом релизе

- Counter-Strike и другие дисциплины (контракт расширения остаётся в проекте).
- Создание пользователем новых клубов, экономика, рынок трансферов, контракты, зарплаты, торговля персонажами.
- Полная система приглашений/заявок, сложные клубные права, множество одновременно управляемых команд менеджера.
- Лиги, полноценные сезоны, таблицы, плей-офф, глобальные рейтинги и матчмейкинг по навыку.
- Продвинутая прокачка, возраст/травмы/карьерная экономика, система развития NPC, косметика и монетизация.
- Физический футбольный движок, визуальная 3D-игра, управление движением или сторонние игровые серверы.
- Чат, друзья, социальная сеть, сложные истории и искусственно генерируемые конфликты.
- Реалистичные все правила футбола, точный баланс всех характеристик, коммерческая античит-система.
- Мобильное приложение, микросервисы, сложное распределённое масштабирование.

**Безопасность не откладывается:** проверка владения персонажем/командой, защита паролей, валидация входных данных и серверные ограничения обязательны уже в MVP. Нельзя подменять их «проверкой в интерфейсе».

## 4. Пользовательский путь, который проверяем

```text
Зарегистрироваться → Создать PLAYER / MANAGER
  → Выбрать системную команду / получить назначение
  → Посмотреть ближайший матч в реальном календаре
  → Подготовить установку / тактику
  → Подключиться в назначенное время
  → Увидеть LIVE-изменения и выбрать действие в эпизоде
  → Получить завершённый результат и историю
```

Параллельно: участники NPC обеспечивают полный состав, а любой матч без человека завершается по тем же правилам.

## 5. Критерии приёмки MVP (проверяются на работающем приложении)

- [ ] Зарегистрировать пользователя и создать минимум 2 отдельных персонажа без смешения прогресса/прав.
- [ ] Создать игрока, присоединить к системной футбольной команде; создать менеджера и получить законное назначение.
- [ ] Сформировать валидные **11×11** составы с NPC и хотя бы одним человеком.
- [ ] Назначить два матча на известное время; **до старта не показывать симуляцию как LIVE**.
- [ ] Матч действительно идёт **в реальном времени** с новыми событиями и открытыми окнами принятия решений.
- [ ] Законное решение PLAYER меняет результат следующего эпизода; MANAGER меняет тактический расчёт, но не управляет спортсменом.
- [ ] Попытки чужого решения, дубля, смены роли или опоздания отклоняются сервером.
- [ ] Два клиента видят единый счёт, общий порядок событий и один финальный результат.
- [ ] Провести полный матч при **нуле онлайн-пользователей**.
- [ ] Перезапустить приложение во время матча: после восстановления нет двойной финализации, пропавших старых событий или сдвига расписания.
- [ ] Открыть историю и увидеть сохранённые результаты и неизменяемые снимки составов.
- [ ] Продемонстрировать тестами, что seed + снимок + версия правил + одинаковые решения воспроизводят одну последовательность событий.

Чекбоксы **не отмечены**: это критерии **будущей реализованной версии**, а не результат текущей Product Discovery.

## 6. Порядок реализации (вертикальными срезами)

1. **[TECH-01](https://github.com/Bleakest/Virtual-competitive-ecosystem/issues/15) / старт:** выбрать лёгкий стек, создать структуру проекта, локальный запуск, проверки качества, базовую схему данных.
2. **ENG-01 / Identity:** рабочие регистрация/вход и персонажи с разграничением прав; первый экран.
3. **ENG-02 / World & Teams:** засеять мир системными командами и NPC, членство и управленческие назначения.
4. **ENG-03 / Calendar:** выставочные события с UTC-расписанием, блокировкой состава и сохранением состояния.
5. **ENG-04 / Simulator:** пошаговый футбольный симулятор с seed, журналом событий, контрольными тестами и фоновым продвижением.
6. **ENG-05 / Live Participation:** LIVE-экран, эпизоды для обеих ролей, дедлайны, офлайн-автоматика.
7. **ENG-06 / Demo & QA:** end-to-end тесты, рестарт/повторы задач, сценарий двух реальных пользователей, полировка удобства.

Каждый срез должен запускаться и проверяться **самостоятельно**, а не существовать набором пустых сервисов. Предпочтителен простой модульный fullstack-монолит на старте; **конкретный стек ещё выбирается** в TECH-01.

## 7. Риски и критерии пересмотра

| Риск | Как минимизировать |
|---|---|
| Слишком долго ждать матча | В демонстрационной среде генерировать ближайшие события с конфигурируемой частотой; в настоящей игре календарь останется честным |
| Пользователь подключился поздно | Текущее состояние + новые допустимые окна, без перемотки чужого матча |
| Никого нет онлайн | Обязательный автоматический проход полного матча |
| Нет чувства влияния на игру | Измеримые изменения распределения исходов от действий, простые объяснения эпизодов и тесты |
| Масса футбольных правил | Начать с событийной модели «владение → атака → удар → гол», не с физики 22 футболистов |
| Грязные истории/дубли после сбоя | Снимок матча, step/version, журнал событий и идемпотентная финализация |

## 8. Что остаётся открытым при закрытии Discovery

- Конкретный технологический стек и схема хранения, инфраструктура разработки/деплоя.
- Прототипные коэффициенты характеристик, вероятностей и частота игровых эпизодов.
- Окончательная длительность матча и частота расписания **после тестирования UX**.
- Визуальный стиль, детализация экрана матча и удобство наблюдения.
- Юридические вопросы названий/брендинга реальных турниров (в MVP использовать вымышленные клубы).
- Масштаб и дальнейшая дорожная карта после первой проверяемой версии.

Это **вопросы реализации**, а не причина откладывать первые коммиты кода.

**Итог DISC-10:** границы MVP определены, обязательное и отложенное разделены, критерии работоспособности и последовательность реализации записаны. Product Discovery даёт достаточно контекста для начала TECH-01.
