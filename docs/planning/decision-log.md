# Decision Log — Product Discovery

**Обновлено:** 2026-11-08

Журнал отражает согласованные решения, изменения ранее принятых решений и открытые вопросы. Продуктовые принципы не следует трактовать как утверждение технической реализации или состава MVP.

## 2026-11-01 — Project Brief v0.1

- **DEC-001:** один аккаунт допускает нескольких персонажей.
- **DEC-002 (заменено 2026-11-02):** первоначально предусматривались три роли: игрок, менеджер и организатор.
- **DEC-003:** базовая роль персонажа неизменна.
- **DEC-004:** каждая роль имеет собственный процесс создания и функциональность.
- **DEC-005:** персонаж-игрок специализируется на одной дисциплине.
- **DEC-006 (уточнено):** менеджер может работать с несколькими дисциплинами; упоминание организатора больше не действует.
- **DEC-007 (уточнено):** менеджер не может одновременно быть действующим игроком в рамках того же персонажа.
- **DEC-008:** различные спортивные и киберспортивные дисциплины с разными правилами.
- **DEC-009:** матчи симулируются самой платформой, без интеграции с настоящими игровыми серверами.
- **DEC-010:** виртуальные участники обеспечивают функционирование мира при отсутствии большой аудитории.
- **DEC-011:** инженерная сложность должна поддерживать интересный продукт и профессиональное развитие автора.

| ID | Решение | Статус |
|---|---|---|
| DEC-012 | Две пользовательские роли — **игрок и менеджер**. Карьера организатора исключена, но организация соревнований остаётся частью мира. Заменяет DEC-002. | Согласовано |
| DEC-013 | Менеджер совмещает управление клубом и тренерские решения. | Согласовано на уровне концепции |
| DEC-014 | Общий онлайн-мир существует непрерывно; календарь и проведение матчей привязаны к **реальному времени**. | Согласовано на уровне концепции |
| DEC-015 | Совмещаются карьера и тренировки, предматчевые установки и выбор действий в ключевых эпизодах симулируемого матча. Это не обязательный набор MVP. | Согласовано на уровне концепции |
| DEC-016 | Реальные пользователи и NPC могут взаимодействовать в одном мире; отсутствие людей не останавливает соревнования. | Согласовано на уровне концепции |
| DEC-017 | Отдельную механику искусственно генерируемых сюжетных историй, драм и конфликтов не разрабатывать. Обычные игровые взаимодействия сохраняются. | Согласовано |
| DEC-018 | Ориентир — широкая аудитория, интересующаяся игровыми карьерами; обе оставшиеся роли значимы в долгосрочной концепции. | Продуктовый ориентир; рыночный спрос не проверен |

## 2026-11-08 — DISC-02/03: утверждено владельцем

См. [Accounts & Characters](../product/accounts-and-characters.md) и [Role Lifecycles](../product/role-lifecycles.md). Ниже решения, **утверждённые владельцем 2026-11-08**. Детали, которые документы прямо относят к открытым вопросам, не считаются утверждёнными:

| ID | Предложение | Статус |
|---|---|---|
| DEC-019 | Отдельные `Account`, `Character` и ровно один ролевой профиль `PlayerProfile` / `ManagerProfile`; карьеры и прогресс изолированы. | Согласовано 2026-11-08 |
| DEC-020 | Выбор персонажа — контекст сессии; сервер проверяет владение, роль и полномочия при каждом действии. | Согласовано 2026-11-08 |
| DEC-021 | Нельзя одновременно управлять несколькими персонажами одного аккаунта в одном матче; детализация конфликтов интересов — позднее. | Согласовано 2026-11-08 |
| DEC-022 | Карьерные состояния персонажа: активен/архивирован; наличие команды и участие в матче — отдельные отношения и состояния. | Согласовано 2026-11-08 |
| DEC-023 | Числовой лимит персонажей не фиксируется до DISC-10; в реализации лимит должен конфигурироваться. | Согласовано 2026-11-08 |
| DEC-024 | Формализовать этапы игрока и менеджера без роли организатора; поведение офлайн и алгоритмы не определять до DISC-07/08. | Согласовано 2026-11-08 |

**Важно:** владелец подтвердил DEC-019—024. Ранее принятые DEC-001—018 сохраняют статус. Числовые лимиты, игровые алгоритмы, антизлоупотребления и прочие явно отложенные детали ещё не утверждены.

## 2026-11-08 — DISC-04/05: рабочие решения по делегированию

См. [World & NPC](../product/world-and-npc.md) и [Disciplines](../product/disciplines.md). Владелец делегировал выбор **разумных базовых правил**; ниже закреплена рабочая база, а не утверждены алгоритмы, параметры баланса и состав MVP.

| ID | Рабочее решение | Статус |
|---|---|---|
| DEC-025 | Один общий логический мир, календарь и система соревнований; отдельной карьеры организатора нет. | Принято в рамках делегирования |
| DEC-026 | NPC — самостоятельный системный участник с сохраняемой карьерой; пользовательский Account ему не нужен. | Принято в рамках делегирования |
| DEC-027 | Временное автоматическое управление отсутствующим человеком **не превращает** его персонажа в NPC. | Принято в рамках делегирования |
| DEC-028 | NPC подчиняется общим регламентам роли, дисциплины и матча; поведение можно начать с набора правил без сложного ИИ. | Принято в рамках делегирования |
| DEC-029 | Календарь/матчи/результаты имеют общее ядро; специальные правила и статистика определяются каждой дисциплиной. | Принято в рамках делегирования |
| DEC-030 | Матч фиксирует версию правил дисциплины для сохранения корректной истории. | Принято в рамках делегирования |
| DEC-031 | Футбол 11×11 и Counter-Strike 5×5 — примеры, а не обязательные дисциплины MVP. | Подтверждение ранее принятого ограничения |

**Открыто:** конкретное число NPC, стратегии поведения, клубы и контракты, точные правила составов, длительности матчей, экономика/баланс, симуляция, первая дисциплина и объём MVP (DISC-06—10). Это не скрытые согласованные решения.

## 2026-11-08 — DISC-06—10: базовые решения по делегированию

Полные спецификации: [команды](../product/teams-and-organizations.md), [матчи](../product/competitions-and-matches.md), [симуляция](../product/simulation-principles.md), [сценарии](../product/user-journeys.md), [MVP](../product/mvp-scope.md).

| ID | Решение | Статус |
|---|---|---|
| DEC-032 | Организация/клуб содержит команды, каждая команда относится к одной дисциплине; членство, менеджерские полномочия и матчевые составы — отдельные отношения с историей. | Рабочее решение по делегированию |
| DEC-033 | Игрок имеет одно активное членство в команде своей дисциплины; менеджер действует только по назначению. В MVP не более одного назначения менеджера одновременно. | Рабочее решение по делегированию |
| DEC-034 | Системное соревнование назначает матчи в UTC; матч проходит стадии регистрации, блокировки состава, LIVE и единственной финализации. | Рабочее решение по делегированию |
| DEC-035 | Счёт не вычисляется заранее: симуляция идёт по реальному времени, принимает решения в открытые окна, работает без пользователей онлайн. | Рабочее решение по делегированию |
| DEC-036 | Матч использует зафиксированные составы, версию правил, seed, упорядоченные события и решения для воспроизводимого расчёта. | Рабочее решение по делегированию |
| DEC-037 | Сервер проверяет права и дедлайны каждого решения, обрабатывает повторы идемпотентно и использует автодействия при отсутствии человека. | Рабочее решение по делегированию |
| DEC-038 | Сквозные пользовательские сценарии только двух ролей (игрок и менеджер); организатор соревнований — системный механизм, а не персонаж. | Подтверждение DEC-012 |
| DEC-039 | Для MVP выбрана **упрощённая футбольная дисциплина 11×11** с системными командами, NPC, выставочными матчами около **10 реальных минут** и интерактивными действиями обеих ролей. | Решение для MVP по делегированию, длительность настраивается |
| DEC-040 | MVP не включает другие дисциплины, экономику, трансферы/контракты, пользовательские клубы, лиги и сложные физические движки. | Решение для MVP по делегированию |
| DEC-041 | Product Discovery даёт достаточно требований для начала TECH-01 и разработки; конкретный стек и коэффициенты симуляции выбираются позже. | Рабочее решение по делегированию |

**Принято для рабочей базы, но не утверждено навсегда:** итоговые коэффициенты, частота интерактивных окон, календарная частота, удобная длительность матчей, технология хранения, инфраструктура. Они уточняются при реализации и тестировании; числовые значения MVP не становятся требованиями ко всем дисциплинам.

## Открытые вопросы

Конкретный технологический стек, итоговые значения лимитов/баланса, частота интерактивных эпизодов и матчей, параметры после тестирования UX, экономика/контракты/трансферы, масштабирование, киберспортивные дисциплины и будущие режимы вне MVP.

Основные продуктовые рамки закрыты в DISC-01—10. Оставшиеся решения относятся к техническому дизайну, реализации MVP и будущим версиям.
